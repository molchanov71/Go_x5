# Сервис уведомлений

Автор: Молчанов Степан

## Что делает программа

Программа добавляет уведомления в структуры, относящиеся к интерфейсу ```Notifier```. 
Обрабатываются исключения (например, пустое сообщение). 
Доступны две готовые структуры: ```EmailNotifier``` и ```PushNotifier```.

## Как запустить

Команды выполняются из корня (папка ```3``` в git-репозитории). 

Версия go: ```go1.27.2 linux/amd64```.

Запуск программы: ```go run ./cmd/notify```

Запуск тестов: ```go test ./...```

## Проверенные случаи

Результат успешной отправки: ```заказ готов через <Dispatch/SafeDispatch>```.

Результат отправки пустого текста: возникает ошибка, текст: ```пустое сообщение```, отправка не производится

Результат отправки сообщения в канал с отстутствующей настройкой: возникает ошибка, текст: ```канал <канал>: не задан <адрес/device id>```

Результат паники одного канала: для канала, в котором возникла паника, отправка не производится, для остальных сообщение: ```заказ готов через SafeDispatch```

## Обработка ошибок

Объясните, чем отличаются Dispatch и SafeDispatch. Покажите, где используются errors.Is и errors.As, и почему recover находится вокруг отдельного вызова.

В отличие от SafeDispatch, Dispatch завершается при первой возникшей ошибке и возвращает её. SafeDispatch же пробует произвести отправку во все каналы и сохраняет возникшие при обходе ошибки в срез ```[]error```.

```errors.Is``` используется, чтобы убедиться, что при отправке пустого сообщения была возвращена ошибка ```ErrEmptyMessage```, а также чтобы убедиться, что при панике в канале возвращается ошибка ```ErrNotifierPanic```.

```errors.As``` используется, чтобы убедиться, что при отправке сообщения в канал с отсутствующей настройкой возвращается ошибка, у которой в цепочке есть ```SendError```, а также чтобы записать первую ошибку этого типа по указателю соответствующего типа.
